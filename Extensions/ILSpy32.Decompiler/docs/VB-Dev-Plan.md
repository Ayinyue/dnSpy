## 终态：最终核心目标（Definition of Done）

**使命**：让 dnSpy 对 VB 的反编译输出达到与 C# 输出同等的可信度——每一段 VB 代码都能通过
Roslyn 语义编译，并且**语义与原 IL 一致**；任何一行「看起来对但语义错」的输出都按缺陷处理。

拆成五条可判定的完成条件（全部满足即项目收口）：

1. **零降级**：三个样本所有类型 `ok` / 0 degraded（✅ 已达成，2026-10-31）
2. **零语法错误**：`validate` 全绿，即 0 / 0 / 0（当前 5 / 0 / 1，全部是 `BC30036` 整数字面量溢出）
3. **零真实语义错误**：逐文件语义编译的 realBadFiles → **0**；
   无法归零的部分（互操作类型跨文件、internal 可见性）必须**从度量口径中剥离**并写明证据，
   而不是留在数字里
4. **语义可论证**：每一条被消掉的诊断都有「为什么与原 IL 等价」的说明（README 经验表即此用途）
5. **可复现**：一条命令重跑全部指标，任何人接手 10 分钟内得到与本文件一致的数字

**当前差距**：realBadFiles 1068 / 565 / 10 → 0。剩余可归零部分约 400~500（分布在
`BC30452/BC30401/BC30456/BC32022/BC30521/BC30583/BC31132`），其余为度量口径问题（见第 3 节）。

**两条底线**（与 Action-Plan 第 2 节一致，违反即回退）：
- 不产出「能编译但语义错」的代码；
- 为消一个警告而引入一个新错误，视为净退步。

## 2. 批次明细

### Batch 0 回归基建

- [ ] 把第 4 节三条命令固化成一个脚本（如 `baseline/run-regression.cmd`），一条命令输出三组数字
- [ ] 脚本输出与本文基线表逐项对照，不一致即失败

**验收**：新会话不读文档也能一条命令得到 1068 / 565 / 10。
**说明**：纯工具，不改转换器；若认为没必要可跳过，但每次回归就要手敲四条命令。

### Batch 1 `BC30452` 引用比较漏判（92 个文件，0 噪声）

- [ ] 用 `--whole --id BC30452 --top 3` 取 20 条样本，归类「两侧类型都推不出」的具体形态
- [ ] 扩展 `ExpressionTypeResolver.GetTypeName` 的覆盖面（候选：属性访问链、方法返回值、数组元素、`DirectCast` 结果）
- [ ] 单类型回归 + 全量回归

**已知事实**：`IsReferentialComparison` 已是「任一侧已知引用即判 `Is`」；剩余 92 条是**两侧都未知**。
**做法约束**：只加「确定是引用」的来源，不加猜测；`GetType` 反射兜底对 `Global.` 开头的名字大概率无效，别指望。
**风险**：把值类型比较误写成 `Is` → 新增 `BC30037` 类错误。缓解：只有 `Classify()==true` 才改写，值类型与未知都保持 `=`。
**验收**：`BC30452` ≤ 50；`BC32022`/`BC30456` 不回升。

### Batch 2 `BC30401` 签名不符归类（109 个文件，56 噪声）

- [ ] `--whole --id BC30401 --top 3` 取样 ≥ 20 条，按「ByRef / Optional / 泛型实参 / 元组 / 其它」分类
- [ ] 每类单独定性：是转换器给的签名错，还是 VB 更严格
- [ ] 只修「转换器签名错」的那几类；VB 语义上确实不兼容的记录为已知限制

**已知事实**：`Optional` 已从接口元数据复制（提交 `272309359`）；`BC30401` 比 `BC30149` 多 12 是**更精确**的诊断，不是回归。
**风险**：`ResolveInterfaceDefinition` 按「名字+元数」匹配，重载多的接口可能错配——不要扩大它的匹配面。
**验收**：`BC30401` ≤ 80；`BC30149` 不回升。

### Batch 3 `BC30456` 成员不存在定性（229 个文件，12 噪声）

- [ ] 取样 20 条，分「跨 dump 文件类型」（度量口径）与「真缺成员」（转换缺陷）
- [ ] 真缺成员的：定位是属性/字段没生成，还是访问器形态问题
- [ ] 输出定性结论写进 README，再决定修哪些

**代表样本**：`'ImageReference' is not a member of 'BookmarkInfo'`。
**验收**：定性报告入档；realBadFiles 下降或明确「全部为口径问题」。

### Batch 4 事件族（`BC32022` 266 / `BC31132` 81）

- [ ] `BC32022`：放宽事件副本抑制的「恰好两次引用」条件（允许守卫与调用跨层级/多一层中间量），逐个样本验证语义
- [ ] `BC31132`：为带真实逻辑的自定义事件合成 `RaiseEvent` 访问器——**语义难点**：VB 自定义事件没有隐式 backing 字段，需要先确认类内是否有可用的私有委托字段，没有就不能合成
- [ ] 单类型回归 + 全量回归

**已知事实**：自动事件（双访问器都标 `[CompilerGenerated]`）已改写字段式事件；剩下 81 个是**真带逻辑**的自定义事件。
**风险**：合成 `RaiseEvent` 若语义不成立，宁可保持 BC31132 显式报错。
**验收**：`BC31132` = 0 或剩「确实无法表达」并写明；`BC32022` 下降且 `RaiseEvent` 输出与 C# 调用点一一对应。

### Batch 5 重复实现与重载歧义（`BC30583` 45 / `BC30521` 108）

- [ ] `BC30583`：剩余代表 `ITextView.GetTextViewLineContainingBufferPosition`，查去重键为何没命中（疑似接口继承链上同名成员）
- [ ] `BC30521`：同名不同签名的重载歧义，可能需补 `Overloads` 或区分实现
- [ ] 全量回归

**风险**：去重逻辑改宽会重新引入 `Implements I.Foo, I.Foo`（上一轮已踩过：按名字去重会吞合法重载）。
**验收**：两者下降；`BC30149` 不回升。

### Batch 6 度量口径改造（可选，需用户拍板）

- [ ] 方案 A：`compile --whole` 作为默认口径，逐文件仅作调试
- [ ] 方案 B：给编译单元加 `InternalsVisibleTo` 式可见性，让 internal 成员可见
- [ ] 方案 C：维持现状，仅在报告里突出 Noise 列

**动机**：`BC30002`(669/563 噪声)、`BC30389`(2408 全噪声) 占了指标大头，剥离后 realBadFiles 才反映真实缺陷密度。
**不做代码改动**；只改 `baseline/Program.cs` 与报告口径。
